# Changelog

All notable changes to this project are documented here.

Format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project doesn't follow strict semantic versioning (it's a classroom tool, not a library), but version numbers roughly mean:

- **Major (v1.0.0 → v2.0.0):** big changes, possibly a new data format
- **Minor (v1.0.0 → v1.1.0):** new features
- **Patch (v1.0.0 → v1.0.1):** bug fixes only

## [Unreleased]

### Added

- **The throwaway localhost servers development sessions leave running are now cleaned up automatically.** Looking at `app.html` in a real browser means starting a small local web server, and nothing ever stopped one again — the session ended, the server kept listening. Thirteen were found running at once on one machine, five of them from the previous day and no longer answering at all; only one belonged to a session that still existed. A hook now reaps them: **on session start** it kills servers whose session is gone, and **on session end** it kills the ones that session itself started. The two layers are not redundant — session-end never fires when a session is force-quit or crashes, which is exactly how all thirteen accumulated, so the session-start sweep is the one that actually holds. **It is built to under-kill rather than over-kill**, because the same `node` that runs a preview server also runs the editor's own background services, and killing one of those breaks a live session. A process is only ever touched if it is `node`, *and* is listening on a TCP port (the editor's services talk over stdio and never listen, so they cannot match), *and* its command line looks like a dev server, *and* it is on a dev port or references this repo — and even then, never while a live session sits anywhere up its parent chain. Anything ambiguous is left running. A newly orphaned server gets a 30-minute grace period so a preview still open in a browser tab isn't yanked out from under you, and **every kill is logged** to `.claude/reap-dev-servers.log` with the port, age and command line, so a surprise is always explainable afterwards. A server started by hand from a terminal has no session above it and so cannot be told apart from an abandoned one — its port can be pinned (`MENCHMARK_REAP_SKIP_PORTS`) and it is then never touched. Can be run by hand, including a `-DryRun` that reports what it would kill and touches nothing. Dev-only — no app behavior changes, nothing touched in the app or its data. See `.claude/hooks/reap-dev-servers.ps1`.

- **Code size — a − / + on the class sheet that decides how big the codes and photos print, and a List that sizes itself.** A class of 25 with a photo *and* a code in every seat, and the activity codes underneath, did not fit one page: the codes are most of a card's height, that height was fixed, and the only ways out were to drop the photos, drop the activity codes, or print two pages — each of them giving up something the sheet is for. **Code size** now sits on the **Seating chart &amp; print** toolbar with a **−**, a percentage, and a **+**. Each press is one step (150% down to 50%), and every seat's code and picture move together, so a sheet that ran three inches long comes back onto the page without losing anything off it. Measured on a real 25-boy 5×5 chart with photos, codes and the activity footer: **1052px of page used at 100%, 966px at 60%** — the same sheet, comfortably inside the paper. It also goes the other way: a small shiur, or a Landscape sheet, can have **bigger codes than before** — worth doing if you scan from across the room. **What the sizes actually mean on paper:** 100% is exactly the size every sheet prints today, and 60% is a code about ⅜ of an inch square, which a handheld scanner still reads comfortably. Below that you are into territory that depends on your printer, so **print one card and scan it before you print a set**. **The seating chart never resizes itself.** You laid that room out; nothing on it changes behind your back, and a sheet you have set up prints exactly as it did before this update. **List (A–Z) is the opposite, and now sizes itself.** It is the automatic layout — it orders itself alphabetically and takes its columns from the paper — so it now **shrinks the codes on its own, step by step, until the whole class lands on one page**, never going bigger than the size you set and never below 60%. When it has shrunk, the readout says so (*auto 70%*), so you can see what you are getting. If even 60% will not fit — usually a long activity-codes block rather than the boys — it puts your own size back rather than handing you two pages of tiny codes, and the existing fit warning under the preview explains what to try. **The + button tells the truth about its own limit:** when a code already fills its half of the card — which is the normal state on a 4-column chart in *QR code + photo* — pressing + cannot make it bigger, so the button is greyed with a note pointing at fewer columns or Landscape rather than quietly doing nothing. **Data:** one new field, `data.seatPrintOpts.iconScale`, backfilled to `1` in `load2fix()` — 1 being the size every sheet already prints at, so **a save made before this existed comes off the printer identical to the way it does today; nothing repaginates for anyone**. The value is clamped to 0.5–1.5 on load, because it is multiplied straight into the sheet's sizing: a zero, a negative or a string in a hand-edited backup would otherwise collapse every code on the page, and the codes are the sheet. Purely additive, no `DATA_VERSION` change, `migrateData()`/`load2fix()` in sync with `test-migration.html` and four new checks there covering the backfill, a saved size surviving a reload, and repair of a zero, a string and an out-of-range value (266 checks, 0 failures).

- **The seating chart on your screen now offers the same four cards the printed sheet does — including the boy's picture and his code together.** The printed sheet gained a photo-beside-the-code card (below); the live chart could not do it at all. It had one **⛶ Show codes** button, on or off, and turning it on *replaced* every boy's face with his QR — so a rebbi scanning off the smartboard could no longer see who he was scanning, which is the one thing the chart is for. That button is now an **Avatar** picker carrying **the same four choices, in the same order, with the same names** the class sheet uses: **QR code**, **QR code + photo**, **Student photo**, **None**. Pick *QR code + photo* and each seat shows the face and the code side by side with the name underneath, exactly like the printed card. **It is the same setting for the whole Dashboard** — List mode gets the identical card, because the class sheet has always built its List and its seat grid from one card and the screen now does too. **The codes have not changed**: a student code on screen is the same code that prints on his label and the same code the sheet carries, so scanning the screen and scanning paper still do exactly the same thing. **The two Activity-code modes are deliberately screen-less** — a merged `PA:` code is for scanning straight down a printed grid with no arming step, and on the live chart you already arm an activity by tapping it. **Arranging still never shows codes**: drag seats and the cards fall back to faces, then return to the mode you picked when you press *Done arranging* — the picker keeps showing your choice throughout. **It still disarms on a restart**, the same as before: the two code modes reopen as *Student photo* — faces, names and scores — so you never come back to a smartboard showing QR codes where the class expects names. *Student photo* and *None* carry no codes and so are remembered normally; they are a way of looking at the class, not an armed state.

- **Scores can now stay on the chart when the codes come on.** A **Points** toggle sits beside the Avatar picker, matching the class sheet's own Points checkbox and independent of it and of the card mode. Until now the live chart showed each boy's score whenever codes were off and *silently dropped it* whenever they were on, with no way to keep it — so a rebbi scanning off the screen could not see where anybody stood. It defaults **on**, which is what every chart shows today in the state it opens in, so nothing looks different until you turn it off. Works in List mode and the seating chart alike.

- **Data (both of the above):** two new fields, `data.seatCardMode` (`"qr"` / `"qrphoto"` / `"photo"` / `"none"` — the same vocabulary `data.seatPrintOpts.avatarMode` already uses, read through the same two helpers so a combined value cannot be understood by one renderer and missed by another) and `data.seatShowPoints`. **Purely additive, no `DATA_VERSION` change, and nothing can be lost.** The old `data.seatScanMode` boolean is still written and still backfilled — it is kept exactly in step, it simply stopped being what the chart reads — so an existing save, a backup file and the Google Sheet all still carry the field they always did. A save predating these fields derives its mode from that boolean and, since the restart behaviour turns a code mode back into *Student photo* anyway, **every existing rebbi opens on precisely the chart he opens on today**. `migrateData()`/`load2fix()` stay in sync with `test-migration.html` (261 checks pass, including the corrupted-data scenarios).

- **Shulchani Mode now comes with the coins themselves as codes — and you set an activity's worth by picking a coin, not by counting Prutot.** Turning Shulchani Mode on used to change the *words* and nothing else: the Activities tab started saying "Prutot" where it had said "Points", and your activities stayed at whatever they were. Since the three that ship with the app are worth **1** each, that made every one of them worth **one Prutah** — the smallest coin there is — putting a Darkon **1536 scans** away and leaving most of the currency somewhere no boy in the class would ever reach. **Two things change, both only inside Shulchani Mode.** First, **the seven denominations are now scannable codes in their own right** — a **+ Dinar** and a **− Dinar**, a **+ Maah** and a **− Maah**, and so on for all seven — printed together under their own **Coins** heading on your class sheet, so a rebbi with the sheet in his hand can give a boy a Sela without first working out that a Sela is 768 of anything. They arrive the first time you land in Shulchani Mode and they are ordinary activities from that moment on: rename them, re-value them, delete the ones your classroom doesn't use. **The seven deductions arrive switched off on screen** — fourteen buttons is more than the Record tab wants, and taking back a Darkon is not a tile to reach past by accident — but **they all still print**, and the **Show** tick beside any of them puts it on the Record tab. Second, **an activity's value is now entered as a coin and a count** — "1 Maah", "3 Isar" — with the Prutot it comes to shown beside it, on both the Add form and every activity in the list. The stepper that made you type **192** to mean a Dinar is gone from Shulchani Mode; **points mode keeps it exactly as it is.** A value that isn't a whole number of any single coin still reads back correctly (200 shows as 25 Isar), so nothing you have already set becomes uneditable. **Your three starter activities get sensible coin values on the way in** — On time becomes **1 Isar**, Davening nicely and Learning nicely **1 Maah** each — but **only if you never touched them**. An activity you renamed or re-valued yourself keeps your number, always. **Data:** one new field, `data.shulchaniCoinsSeeded`, backfilled `false` in `load2fix()`, plus a `coin` marker on the seeded codes. Purely additive — no `DATA_VERSION` change, nothing existing renamed, converted or removed. **Switching back to points never deletes a coin code**: they carry the `coin` marker and are simply not shown, not scanned and not printed while balances are counted in points, so a rebbi can move between the two modes as often as he likes and find his codes exactly where he left them either way. A printed coin code scanned while Shulchani Mode is off says so plainly rather than quietly awarding a bare 192. **A rebbi already running Shulchani Mode gets the coin codes on his next load, and his activity values are left completely alone** — he has been scanning with what they are worth for weeks, and a routine load is not the moment to change that under him; only deliberately switching the mode on re-values the untouched starters. The migration harness carries the same seeder and passes: a points-mode save comes through with no coin codes and its values untouched, an already-Shulchani save gets exactly fourteen, and loading it again never doubles them.

- **Menchmark now notices when you haven't backed up in a while, and says so once — because until now it genuinely had no idea.** Your scores live in this browser, and the one thing that gets them back if that browser is ever cleared is a backup file. The app has always had the button; what it never had was **any record that you had ever pressed it**. No date, no timestamp, nothing — so a rebbi six weeks past his last backup and a rebbi who backed up this morning looked exactly the same to the app, and it could not have warned either of them. It can now. **One amber line across the top of the page, no more than once a week**, saying how long it has been, with **Back up now** — the same download you already use — and **Not now**. **It sits above whichever tab you are on**, so it is not hiding on the one tab you had no reason to open, and it **never prints**. **It is deliberately hard to trip.** It stays quiet for the first week, quiet on a class with no students in it yet (a brand-new install has nothing to lose, and a warning is not the first thing you should see), and quiet in preview mode, where nothing is being saved anyway. **Not now** silences it for the rest of the sitting — it comes back another day, but it will not follow you from tab to tab. **Backing up marks it, wherever the backup came from**: the Download button on Backup & Sheets, and the two safety copies the app already saves for you by itself before a Shulchani-mode switch. The standings CSV and the Log CSV deliberately **don't** count — those are reports to read, not files you can restore from, and letting a report silence the warning would quietly leave a rebbi with no way back. **Data:** two new fields, `data.lastBackupAt` and `data.backupNudgeSince`, both backfilled in `load2fix()`. **There are two rather than one on purpose.** If the app only stored "last backup" it would read *never* for every existing save, and every rebbi already using Menchmark would be met by a warning the moment he loaded this update — for something he may well have been doing by hand all along, which the app simply cannot see, since it can't look at files on your computer. So the second field stamps **the moment you first load this version**, and the countdown starts from there: **nobody is warned on day one, and the first reminder is a full week away.** Nothing is converted, nothing is renamed, nothing existing is read destructively, and no `DATA_VERSION` change — a save from before this update opens exactly as it always has, only now the app can keep count. `migrateData()`/`load2fix()` stay in sync with `test-migration.html`.

- **A boy's picture and his QR code in the same card, side by side — you no longer have to choose.** The class sheet's **Avatar** picker made the photo and the code alternatives: a seat could show one or the other, so a rebbi who wanted to *recognise* a boy and *scan* him had to print two sheets and look between them. Two new options, **QR code + photo** and **Activity code + photo**, put both in one card — **face on the left, code on the right, name underneath** — so you find the boy by looking and score him from the same card. **Side by side rather than one above the other, deliberately.** A seat card is about 1¼ inches wide with a ⅝-inch code centred in it, so close to half its width was already sitting empty while its *height* was the thing that pushed a sheet onto page 2. Stacking the picture above the code would have spent the scarce dimension to save the plentiful one. Across, it spends the empty width instead: **on a 6-column chart the picture is effectively free** — a card grows by about one pixel — and it is only the wide cards, 4 and 5 columns, that pay roughly a quarter inch per row for a noticeably bigger face. **And the picture is a usable size**, which was the point: it scales with the card, from about half an inch on a 6-column chart up to ¾ inch at 4 columns or in Landscape, and it is **cropped square here rather than round**. A circle throws away the corners of an already small photo — at this size that is most of a boy's hair and chin — so the square crop shows a bit over twice the face of the photo-only mode at its smallest and about five times at its largest. Round avatars are unchanged everywhere else in the app. **The codes are the same codes.** *QR code + photo* prints the identical student code *QR code* always did, and *Activity code + photo* prints the identical `PA:<student>:<activity>` merged code *Activity code* always did — verified by comparing the generated images, not assumed — so a code scanned off a photo sheet is indistinguishable from the same code scanned off the sheet you print today. Both new modes work in **List (A–Z)** as well as the seating chart, because the two layouts share one card. **The three modes you already use are untouched, down to the page height** — a code on its own, a photo on its own and *None* keep the exact markup and therefore the exact printed size they have always had, so **a one-page sheet a rebbi has set up stays a one-page sheet**; the side-by-side row exists only when both are actually being printed. If a photo sheet does stop fitting, the existing warning under the preview says so (confirmed against a 48-boy 12×4 sheet). **Data:** no new field and nothing converted — `data.seatPrintOpts.avatarMode` is the same string it has always been, and this only adds two values it may hold. Every value an existing save can carry still means exactly what it meant, so **no rebbi's Avatar choice is changed by this update**; a value that isn't recognised (a corrupt save, a typo) still falls back to *QR code* as before. Purely additive, no `DATA_VERSION` change, and `migrateData()`/`load2fix()` stay in sync with `test-migration.html`.

- **The class sheet prints as a plain alphabetical list too, not only as a seating chart.** A **Seating chart / List (A–Z)** switch now sits at the front of the **Seating chart &amp; print** toolbar. **List prints the whole class alphabetically by last name** — the same order the Dashboard's List mode and the Students tab already use, so the three never disagree — with no desks, no *Front of room* and no empty seats. It is the sheet to print before you have arranged anybody, and the one to print when the page is really just for reading names off. **The cards are identical either way**: same QR code, same photo, same points, so a code scanned off the list is the same scan as off the chart. Avatar, Points, the Activities footer and Portrait/Landscape all still apply; **Rows/Cols and Rebbi's view are hidden in List**, because both describe a room — how many desks across, and which end of it you are standing at — and a list has no room. **Printing a list never creates a seating chart.** Opening this page in Seating chart still seats anyone unplaced so the sheet is ready, and switching back to Seating chart does the same — but a class you only ever printed a list for is left with no chart at all, exactly as you left it. **Data:** one new field, `data.seatPrintOpts.layout`, backfilled to `"seating"` in `load2fix()`; anything that isn't exactly `"list"` — a save predating the field, a corrupt value — becomes `"seating"`, so **no existing rebbi's sheet is switched to List for him**. Purely additive, no `DATA_VERSION` change.

- **List and Seating chart are now one switch, on their own line — they are a mode, not two more buttons.** The two sat as the first pair in a single wrapped strip alongside **Show codes**, **Show activities**, **Rebbi's view** and the layout controls, so the one control that decides *what you are looking at* had exactly the same weight as the ones that only decorate it — and on a narrow screen it could wrap into the middle of the row. They are now a **segmented pair on their own line above the toolbar**: one control with two states, List on the left, Seating chart on the right, the active one filled in. Everything else stays in the toolbar underneath, where it reads as what it is — options that apply *within* whichever mode you have picked. **Nothing about what either mode does has changed**, both still remember your choice exactly as before, and the pair shrinks to match on the full-screen chart.

- **A class you haven't arranged yet shows your class list, not a grid of empty desks.** List / Seating chart is one setting shared by every class, but each class has its own chart — so a rebbi who arranged his first shiur and left the panel on **Seating chart** would switch to a newly-imported class and be met with rows of boxes reading "Empty seat" and **not one of his students on the screen**. The unplaced boys were only ever drawn while arranging was switched on, so there was nobody to tap, and nothing saying why. That class now shows **the class list instead — alphabetically by last name**, exactly as List mode has always sorted, with a line above it saying there is no chart for this class yet and a **⚙ Set up seating chart** button that opens the chart and starts placing boys in one press. **Your setting is not changed** — it still says Seating chart, so the class you *did* arrange still opens straight into its chart, and the moment you seat one boy in the new class it stops being empty and stays on the chart you just built. A chart holding only boys who have since been deleted or moved class counts as empty too, which is the one other way this used to happen. **Pressing "Seating chart" on a class with no chart takes you into arranging** rather than appearing to do nothing. **Nothing about any seating chart is created, changed, or deleted by any of this** — it only decides which of the two existing views is drawn. It can be switched off in **Settings → Scan Tab — Tap Panel**, which puts the empty grid straight back. **Data:** one new field, `data.seatListFallback`, backfilled to `true` in `load2fix()` for existing saves as well as new ones — the state it replaces is a dead end nobody chose, so there is nothing to preserve. Purely additive, no `DATA_VERSION` change, and it reads `data.seating` without ever writing to it.

- **Recognize date range: Today, Custom (this week / this month / pick dates), and All-time — and it's now remembered.** The Leader Board's range picker used to reset to All-time on every reload no matter what you'd chosen, so it never stayed on the range you actually wanted for the rest of the period. **Today** is new outright — see just what's been earned since the day started, useful for a rebbi checking in mid-lesson. **Custom…** is now a bucket rather than a single calendar picker: pick **This week** or **This month** for an instant, no-typing range, or **Pick dates…** for the existing From/To calendar — the old Custom range date fields are unchanged and still drive it exactly as before. Clicking **Custom…** re-opens on whichever of the three you used last. **All-time stays the default** for anyone who has never touched the control, so nothing changes until a rebbi actually picks something. **🏆 Contest is unaffected**, and deliberately never becomes the remembered choice — it is driven by whether a contest is actually running rather than a saved preference, so it can never go stale once a contest ends. **Data:** two new fields, `data.standRange` (the active range) and `data.standRangeCustomSub` (the last-used Custom sub-choice), both backfilled with safe defaults (`"all"` / `"week"`) in `load2fix()` — purely additive, no `DATA_VERSION` change, and a save from before this update opens exactly as it always has.
- **The printed class sheet lays its codes out the way the chart on screen does — including the one-row option.** The chart under the Dashboard got **▤ One row / ▦ Grouped** and a **1 → 2 → 3 wide** control; the sheet did not, so the same codes came off the printer in a shape you had no say over: three sections stacked one under the other, each running the full width of the page. Both controls now sit on **Print my class sheet** too, next to the Activities-footer tick, worded exactly as they are on the chart. Grouped now prints the sections **side by side in boxes** rather than stacked — the same shape as on screen, and it takes far less of the page, which matters because this block running onto page 2 is the failure this sheet has always been one code away from. **The two are set separately on purpose.** A smartboard and a sheet of paper are different shapes, and a rebbi may well want three across on the board and a single row in his hand. **Which** codes appear, what section each one is in and what order they come in stay shared, because that is what **Choose codes** governs and the board and the paper must never disagree about it. **Data:** two new fields on `data.seatPrintOpts` (`actGrouped`, `actCols`), backfilled in `load2fix()` to grouped/2-wide — which is what every existing sheet already prints, so nothing changes for anyone until he presses the button. Purely additive, no `DATA_VERSION` change.
- **The separate code arranger is gone from the class sheet page — everything it did is on the sheet itself.** Choosing, re-ordering and moving codes were already there; the last two reasons to open the old box have joined them. **Click a section's name to rename it** — "Points" becomes "Middos" and it changes on the printed sheet, the chart and the activity menu together; clearing it or typing the built-in name back puts it as it was, so a rename is never a one-way door. **All** and **None** sit on the codes block they act on. The picker still exists and is unchanged — it is what **⚙ Choose codes** on the seating chart and **Choose codes** on Print: Activities open, since neither of those pages has a sheet to edit.
- **One chart on the class sheet page, not two.** The page carried a seating editor at the top *and* the printed preview underneath — the same chart drawn twice, so you arranged boys in one box while looking at the other to see what you had done. The editor is gone and **the preview is the editor**: drag a boy from one desk to another, press a seat's **✕** to empty it, and he drops into a *Not yet seated* tray under the sheet to be dragged or tapped back. **Rows and Cols moved up to the toolbar** — they were the one thing in the old box with nowhere else to live — and changing them still never moves a boy you have already placed. Both charts share one set of drag handlers now rather than the sheet having its own, which is what made two boxes necessary in the first place; and dragging works correctly in **Rebbi's view**, where what you see is reversed but what gets written is not.
- **The mock-up of the class sheet is now the thing you edit.** You could already choose and re-order your codes, but only in a separate arranger full of little chips standing in for the real cards — you changed the list, then looked back at the preview to see what you had done. **The codes on the preview are the controls now:** drag one to re-order it, drag it into another section, and press its **✕** to take it off. Anything you take off drops into a **tray under the codes** — click a name there to put it straight back, or drag it back where you want it. An empty section still shows on screen with a place to drop into, so a section you have cleared out isn't a dead end; it prints as nothing at all. It is the same list and the same order underneath as **Choose codes**, so the two can't disagree — this is the same edit made on the sheet in front of you instead of on a list describing it. **None of the handles print** — the ✕, the tray and the empty-section outlines are all screen-only, so the page that comes off the printer is exactly what the mock-up shows minus the furniture.
- **Every code can be switched on and off from wherever you are looking at codes — including Print: Activities, which had no switch at all.** The on/off choice has always applied to the activity menu (all four code surfaces read the same list), but that page gave you no way to *change* it: a rebbi printing his menu saw ten of his thirteen codes, with **◂ Previous Phrase**, **Next Phrase ▸** and **−Custom** simply absent — they start off — nothing on the page explaining it, and the only switch three tabs away underneath the class sheet. **Choose codes** now sits in that page's toolbar too, opening the same picker, and turning a code back on adds it to the menu in front of you. Between this and the seating chart's own button, **all four surfaces that show codes now offer the switch** — the class sheet, the activity menu, the chart, and the picker itself. The picker's wording follows: it now says plainly that the one list governs all of them, and the bin reads "not on any sheet or the chart" rather than naming one. **Also fixed while here: All and None only redrew half of what they changed.** They rebuilt the sheet but not the seating chart, so emptying the list left the chart still showing every code until something else happened to redraw it. All four surfaces are now redrawn from one place, so the next one added cannot quietly be left out.
- **Choose codes is now reachable from the seating chart itself, not only from the print page.** Arranging on the chart only ever moved *students*, so adding, removing or re-ordering the codes underneath meant going to Run → Print my class sheet — a strange errand when what you want to fix is on the smartboard in front of the class. **⚙ Choose codes** now sits in the chart's own toolbar, alongside Grouped and the width button, and opens **the same picker** — the actual one, not a copy of it, so there is no second list to keep in step and a code you drag on the chart has already moved on the sheet.

- **The activity codes under the seating chart are now grouped, labelled, and yours to arrange — and they finally tell you what they're worth.** The strip of codes along the bottom of the chart was one long wrapped row: every code the same size, in whatever order they happened to be added, with **nothing but a name on each one**. "Chesed" and "Disrespect" looked identical until after you had scanned one at a boy. **Every code now carries its value** — a green `+2 pts`, a red `−1 pts`, or, for the ones that don't score at all, what they actually do (`cycles attendance`, `marks a bathroom pass used`). Same green/red the Record tab already uses, with the tracked codes in the app's ice blue, which is neither. **And the codes are grouped into sections** — Points, Tracked, Navigation — laid out as small grids side by side instead of one endless row, each headed and counted. **These are the same three sections your printed class sheet has always used.** That is the whole point of doing it this way rather than inventing a second arrangement: move a code in **Choose codes** and it moves on the screen and on the paper together, so the chart on the smartboard and the sheet in your hand can never disagree. **If you preferred the old single row, it is still there** — **▤ One row** in the chart's toolbar switches back, and **▦ Grouped** switches in again. Next to it, a width button cycles **1 → 2 → 3 wide**, setting how many codes sit across each section; 2 is the default, 1 suits a phone held mid-scan, 3 a wide smartboard. Both buttons only appear while the codes are actually showing. **Sections can be renamed.** The headings are now editable in **Choose codes** — call them "Middos", "Consequences", whatever your classroom calls them — and the new name appears on the screen and prints on the sheet. Clearing a name puts the built-in one back, which is also how you undo a rename without having to remember what it used to say. **The section *keys* never change**, only what they are called, so renaming can't strand a code you had already filed somewhere. **And removing a code is now a bin rather than a checkbox.** Codes you turn off leave their section and wait in a **🗑 Removed** tray at the bottom of Choose codes; drag one back out, or press ↩, and it returns to the section it was in before — it keeps its place rather than being dumped at the end. Dragging a code out of the bin and onto another code both restores it and files it, in one gesture. **Removing takes a code off the sheet *and* off the chart**, because those two have always shown the same set, and making you remove the same code twice in two places would be a way for them to drift apart. **Nothing about how anything scans has changed** — tapping a code arms exactly what scanning it arms, through the same single entry point as before. **Data:** three new fields, all purely additive and backfilled in `load2fix()` — `data.codeSectionNames` (sparse; a section nobody renamed stores nothing), `data.actFooterGrouped` and `data.actFooterCols`. - **The migration test harness now checks itself for drift against `app.html`, automatically, as part of every run.** `test-migration.html` keeps hand-copied duplicates of `migrateData()` and `load2fix()`, and until now nothing enforced that they stayed current — only a "keep in sync" comment and a command someone had to remember to run. - **A saved contest now keeps its own results, instead of quietly becoming an empty label.** "Save to history" only ever stored a contest's name, dates and mode — never anyone's scores. So a contest you deliberately saved would show its full results for a few days, then start showing *less* than really happened as older scans dropped off the end, and eventually "No scan data found for this contest" — with nothing wrong on screen to tell you the numbers had been shrinking all along. - **Clarified setup instructions** to prevent teachers from accidentally sharing a single Google Sheet link, which would cause data conflicts.
- **"Homework Checked" was selectable in the Tracker tab, silently logging to the wrong place.** Homework has its own dedicated data store (`data.hw`, keyed by date) and its own tab. But the built-in "Homework Checked" activity is flagged `tracked:true` — the same flag used for custom Tracker activities — so it also showed up in the Tracker tab's own activity dropdown. Scanning it from there logged into `data.trackerLog` (Tracker's generic log) instead of `data.hw`, so the scan was recorded but invisible on the actual Homework tab — the two systems never talked to each other. Fixed by excluding "Homework Checked" from Tracker's selectable activities; it now only shows up where it actually belongs, on the Homework tab and via the student's personal "Homework Checked" QR code. Note: any homework scans already mis-logged into the Tracker before this fix remain in `data.trackerLog` and are not automatically migrated.
- **"Homework Checked" had the same disconnect via the printed Activity Menu.** The Tracker-tab fix above didn't cover this second path: the Activity Menu print page (QR Labels → Activity Menu) printed a normal `ACT:` QR code for it with no exclusion, so scanning that code armed it like any other activity — subsequent student scans landed in `data.log`, not `data.hw`, again invisible on the Homework tab. Fixed by excluding it from the Activity Menu entirely, and by having `armActivityByCode()` itself refuse to arm it — covering an already-printed, pre-fix sheet still in a classroom — with a message pointing to the Homework tab or the student's own personal QR code instead.
- **"✏️ Edit phrases" button (Teach view, Pesukim/Mishnayos) permanently invisible.** On first load the app defaults to Chart mode, which explicitly set `teachEditBtn.style.display = "none"` directly on the button. Switching into Teach mode afterward only restored visibility on the surrounding container, never on the button itself — so the phrase split/join editor was unreachable from a fresh page load, even though all of its underlying logic (word-splitting, joining, translation editing) was fully intact. Fixed by resetting the button's own inline `display` on every `renderTeach()` call, mirroring the existing reset already in place for the neighboring "Show all" button.
- **Pasuk dropdown didn't update when navigating in the Matching game.** `navigateToPasuk()` routed Teach-mode navigation through `renderTeach()`, which re-syncs the pasuk dropdown as a side effect — but routed Match-mode navigation straight to `loadPmPasuk()`, which never touches the dropdown. Result: tapping ‹ Previous / Next › while in the Matching game correctly advanced to the next pasuk (the game content updated fine), but the dropdown kept showing the old selection. Fixed by syncing the dropdown once at the top of `navigateToPasuk()`, before branching into either sub-mode.

### Changed

- **Renamed "Bunk" to "Class" throughout the app.** This is a Yeshiva/Day School classroom tool, not a camp app — "Bunk" was leftover terminology. Existing teachers' saved class names are preserved automatically via a one-time migration; nothing needs to be re-entered. Google Sheets already created keep their existing "Bunk/Group" column headers (unchanged, to avoid touching live data); brand-new sheets going forward use "Class/Group."

### Fixed

- **Print bug fix: scan bar and sub-tab icons no longer appear on any printed output.** The `#globalScanBar` element and the `.subtabs-row` / `.subtabs-icons` elements are now explicitly hidden in all `@media print` rules. Previously they leaked into every print job, appearing as stray icons at the top of the page.
- **Seating chart print bug fix:** the scan bar was appearing at the top of seating chart prints.
- **Apps Script (Code 1): Leader Board tab never rebuilt after the first student.** The sort comparator inside `rebuildLeaderBoard()` called `lastFirstKey()`, which exists in the browser app but was never defined in the Apps Script. The function threw a `ReferenceError` on every `doPost` call once 2+ students existed — log rows were written correctly, but the Leader Board sheet tab silently never updated. `lastFirstKey` is now defined in Code 1 itself. Users who already deployed should re-paste Code 1 and redeploy (Manage deployments → ✏️ → New version; your URL stays the same).
- **Undo buttons could reverse the wrong scan.** Deferred Undo buttons (Recent scans panel, History tab, scan strip, Contest views) captured a log array *index* at render time. `addLogEntry()` unshifts the array, so any scan that lands between render and click shifted all indices — the button would silently undo a different student's entry. All deferred handlers now look up the entry by its stable id at click time.
- **History/contest dropdowns closed on clicks inside themselves.** The outside-click handler for the History and Activity dropdowns in the header bar used a selector (`#seatsScanTile`) that matched no element, so every bubbled click — including clicks on Undo rows *inside* the dropdown — was treated as "outside" and closed it. Fixed to correctly identify the dropdown containers.
- **Duplicate event listener on the Contest tab's student filter.** The `#contestHistFilter` select had the same `change` handler registered twice. The second one re-rendered the entire Contest tab on every filter change, wiping each Past Contests card's own local student filter. Removed the redundant registration.
- **Corrupted `localStorage` value crashed the entire app.** `JSON.parse` can succeed on a non-object (`"42"`, `"null"`, etc.); `load2fix()` then threw trying to assign properties to a primitive, producing a white screen with no way to recover. `load()` now only accepts a parsed plain object and falls back to defaults for anything else.
- **Restoring a backup left half the UI showing pre-restore state.** After a JSON restore, the class dropdown still listed the old classes; the tap panel, live board, scan-tab layout, and settings-driven UI (full width, header shortcuts, Hebrew date) all kept the previous session's state until some unrelated action happened to re-render them. The restore handler now explicitly refreshes everything the restored data drives, and runs `migrateData()` for version stamping (same as the normal load path).
- **"Resync all scans" could append duplicate rows to Google Sheets forever.** Log entries rebuilt from a Log CSV, and legacy entries predating the id field, had no `id`. The sheet's dedupe check keys on that field, so every Resync click re-appended id-less entries — there was no way to stop the accumulation. CSV-rebuilt entries now get a stable id at import time, and `load2fix()` backfills ids onto any legacy entries on first load.
- **Game timers (Memory, Match, Quiz, Pesukim Matching) kept firing after navigating away.** The 100 ms tick intervals for the shorashim Memory, Match, and Quiz games, and the Pesukim Matching game, had no self-cancel guard. On a smartboard left running all day they accumulated, touching the DOM of hidden views each tick. Each timer now self-cancels when its view leaves the screen, matching the behavior the Game Show timer already had.
- **Beep sounds silently dropped when the AudioContext was suspended.** Browser autoplay policy can leave a previously-created `AudioContext` in a `suspended` state (e.g. after backgrounding the tab). Subsequent calls to `beep()` produced no sound. `beep()` now resumes a suspended context before playing.
