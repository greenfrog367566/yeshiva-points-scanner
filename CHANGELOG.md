# Changelog

All notable changes to this project are documented here.

Format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project doesn't follow strict semantic versioning (it's a classroom tool, not a library), but version numbers roughly mean:

- **Major (v1.0.0 → v2.0.0):** big changes, possibly a new data format
- **Minor (v1.0.0 → v1.1.0):** new features
- **Patch (v1.0.0 → v1.0.1):** bug fixes only

## [Unreleased]

### Added

- **Groundwork for the Gradebook: one shared way of recording "this student, this thing, at this time" (Phase 2a — no visible change yet).** Attendance, Homework, the Tracker and Bathroom Passes are four separate hand-built versions of the same idea, which is why they each behave slightly differently and why none of them can show you a single picture of a student. This release adds the shared foundation they will all sit on — `data.trackedItems` (the list of things being tracked) and `data.trackedData` (the record of every mark, kept as a timestamped history per student rather than only "what it is right now", so nothing is ever written over). **Nothing looks different in the app yet and nothing you do changes:** Attendance, Homework, Passes and the Tracker all still work exactly as they do today, through their own tabs, storing into their own records, untouched. The new foundation is seeded and empty, waiting for the Gradebook screen (2b) to be built on top of it. Four items are set up ready: **Attendance** (present / late / absent), **Homework**, **Bathroom Pass** (one per week, as now), and one item per tracked activity you already have, each keeping its name. **Homework becomes a four-way cycle rather than a checkbox** — *unchecked → full credit → partial credit → no credit*, then back to unchecked. "Unchecked" and "no credit" deliberately mean different things: unchecked is *not collected yet*, no credit is *handed in but below standard*. A checkbox could not tell those apart, which is exactly the gap this closes. **Your existing data:** the new records start empty rather than being converted from the old ones. This is a deliberate clean start for the summer, while the beta group is small — the old Attendance, Homework, Tracker and Pass records are **not deleted, not modified, and not read**; they stay exactly where they are and keep running their tabs, so nothing is lost and a conversion can still be written later if it turns out to be wanted. Purely additive: no `DATA_VERSION` change, nothing renamed or removed, and the migration harness now asserts byte-for-byte that all four old stores come through a load untouched.

- **Do something to a whole group of students at once, from Run → Students.** Every student row now has a tick box, with **Select all shown** at the top that follows whatever the search and class filter are showing — filter to one class, tick the box, and you have that class. Two things can then be done to everyone ticked. **Assign to class** sets the class for all of them in one action, instead of opening twenty-five students one at a time to move a shiur. **Give points** hands the same amount to everyone selected, with a reason you type — the case it was built for is the day the scanner broke and a whole class is short the points they actually earned: select the boys, enter the amount, say what it was for, done. Negative amounts work too, for a correction that needs to come off. **It is a real scan, not a shortcut round the back.** Every point in Menchmark arrives as a logged event, and History, Undo, Trends and the contest merge all read that log — so a batch award writes **one ordinary log entry per student**, carrying the reason you typed, exactly as though each boy had been scanned. It shows up in History, it shows in each student's breakdown, it goes to your Google Sheet, and **you can undo it**. Nothing sets a total directly. Students who are not in the class currently chosen in the top-right corner are skipped rather than silently included, and you are told who and why. The selection itself is not saved — it is a thing you are doing right now, so it clears when you reload, and no new data is stored for it.

- **Bathroom passes: set how many each student gets.** The limit was fixed at one per week and is now a number you choose, on the Passes tab next to the list it governs. The tab's own wording, the summary line, the per-student badge and the refusal message when a student scans all follow whatever you set — a student on a cap of 3 who has used two sees "2 of 3 used" and is told "1 left this week" rather than being turned away. **Give back** now hands back a single pass rather than clearing the student, so a miscount can be corrected a step at a time. **Everything about existing passes is unchanged:** the default is 1, which is exactly how the app has always behaved, and anyone who had used their pass before this update keeps that use. **Passes still only clear when you press Reset** — nothing rolls over on its own, deliberately; automatic weekly rollover is being designed properly for when Passes moves onto the shared tracked-item engine. **Data:** two new fields with safe defaults (`data.passCap`, `data.passCount`), backfilled in `load2fix()`, no `DATA_VERSION` change. They deliberately sit *outside* `data.passes` so that store stays byte-for-byte identical through a load, which the migration harness asserts and which the tracked-item conversion will depend on.

- **The Gradebook — one grid for everything you track, in Run → Gradebook (Phase 2b).** Phase 2a built the shared record but left it invisible; this is the screen that reads it. Students run down the side, the things you track run across the top, and **the columns come from your tracked items themselves** — add an item and it appears here on its own, with nothing to wire up. That is the whole payoff of the foundation laid last release. **Two filters, because a grid without them is unusable in a real shiur.** *Choose items* picks which tracked items appear as columns — not a nicety, it is what lets the thing fit on a printed page at all. *Dates* is a range, not a single day (Today / Last 7 days / Last 30 days / a range you type), so you can look at three weeks of homework instead of one summary number. **The grid changes shape to suit what you asked for**, without you choosing a layout: one item over a range gives you a column per date; several items on a single day gives you a column per item; several items over a range groups the dates under each item's name and adds a **Total** for each. Only days that actually have something recorded become columns, so three weeks of homework is however many days you actually collected it, not twenty-one empty boxes. Totals read the way each kind of item wants to be read — counts add up, passes show uses, and for a list-type item like Attendance the total shows only the **exceptions** (`L2 A1` — twice late, once absent), since tallying every "present" would just restate the number of columns. Cells use one letter per value with a **key printed underneath**, so a page you hand to someone else explains itself. **Printing prints exactly what is on screen** — the item checkboxes and the date range *are* the print settings, there is no second setup to fill in and no way for the two to drift apart. It prints landscape, with the chrome stripped and the type shrunk to fit; if you have chosen more columns than a page holds, the screen tells you so before you print rather than after. **Nothing about how anything is recorded has changed.** This screen only reads. Attendance, Homework, the Tracker and Passes still work exactly as they do today, on their own tabs, storing into their own records, which this screen never touches. It lives under **Run** because a gradebook is private record-keeping rather than something to put on the board — the eventual split into a class-facing book and a private one is a later phase, and one book in the safer place is the right thing until then. **Because the shared record only starts filling when scanning writes into it (a later phase), the grid will be empty at first** and says so plainly instead of looking broken. **Data:** five view preferences only — which items are hidden, the date mode, the two custom dates, and whether the item picker is open. Purely additive, backfilled in `load2fix()`, no `DATA_VERSION` change, and nothing existing is read, renamed, converted or removed. The hidden-items list deliberately stores what to **hide** rather than what to show, so a tracked item added later still turns up as a column by itself.

- **Your attendance history now appears in the Gradebook (Phase 2c — attendance only).** The Gradebook shipped last release with an Attendance column that was always empty, because Phase 2a deliberately started the shared record from scratch rather than converting anything. This fills it in: every attendance mark you have already taken is copied across into the shared record, so opening Run → Gradebook shows the weeks you actually took, not a blank grid. **Present, late and absent all come across as themselves** — "late" is a real thing you recorded, with its own button and its own status in your Google Sheet, and it is not folded into either of the other two. **Your Attendance tab is completely unchanged** and still works exactly as it does today; nothing has been retired or moved, and this update only *reads* the attendance records — it does not alter, rewrite or delete a single one of them. **One deliberate omission, and it matters.** The Attendance tab marks everyone Present automatically the moment you open it, so you only have to tap the exceptions. That is a good way to take attendance and a bad thing to keep forever: on a day you opened the tab and never marked anyone, the app holds a "Present" for every boy that **nobody actually recorded**. Those are assumptions, not observations, and a gradebook that cannot tell them apart from real marks is worse than one with a gap in it — so they are **left out**. Only marks with a real time on them come across. Every exception you ever tapped — every late, every absent — comes across in full. **The one case this cannot see through:** on any day you pressed **Send Attendance**, the app stamped a time onto those auto-filled records in order to send them, which makes them indistinguishable from marks you made yourself. Those days convert in full, auto-fills included. There is no way to tell them apart after the fact, and inventing a rule to guess would be worse than saying so plainly. **You can see exactly what happened to your own data**: `test-migration.html` now reports the counts for any backup you drop into it — days walked, marks converted, and how many auto-filled assumptions were left out. **Data:** purely additive, no `DATA_VERSION` change. `data.attendance` is untouched and still owns the Attendance tab; the copies are written into the tracked item `ti-attendance` alongside it. **Timestamps are copied, never re-issued** — the Google Sheet decides what to re-send by comparing a record's time against the last send, and the Attendance Log does not de-duplicate, so a rewritten timestamp would push your history into your Sheet a second time as duplicate rows. Nothing here writes a timestamp at all. Running it twice cannot double anything: each mark is matched on its own date and time against what is already stored, so a restored backup or a second load adds nothing. Homework, the Tracker and Passes are **not** part of this and are still parked exactly as they were.

- **The Gradebook is now readable at a glance, and prints one page per thing you track.** The grid was correct but hard to use: undifferentiated rows, uncoloured cells, and a single sheet of paper asked to hold 58 columns. Six changes, all presentation — nothing about what is recorded or stored moves. **Rows alternate light and slightly darker**, so your eye stays on the right boy all the way across a wide grid; the names column and the totals column stripe with everything else. **Cells are colour-coded** — green for present and full credit, brass for late and partial, red for absent and no credit, with brass being the same shade the Attendance tab already uses for a late boy. The colour is always *in addition to* the mark, never instead of it, so nothing is lost if you can't tell the tints apart or you print in black and white. Your own scales stay uncoloured, because the app has no way to know whether one of your options is the good one or the bad one, and guessing would be it telling you something about your classroom that it doesn't know. **Each date now shows the day of the week underneath it**, so *Jul 16* is also visibly a Thursday. **Weeks are grouped Sunday to Friday** with a rule down the first day of each week and alternate weeks shaded a shade apart in the header — so a fortnight reads as two weeks rather than eleven columns. **A short "Who" column is pinned on the right** carrying each boy's initials, so the far columns can still be read without scrolling back to the names; two boys with the same initials get told apart automatically, and the full name is still there on hover and for a screen reader. **And printing now gives each tracked item its own page** — Attendance on one sheet, Homework on the next — each with its own heading, its own dates and its own key, so a single page handed to a menahel explains itself. That is what makes the thing printable at all: what was one 58-column sheet that fitted nowhere is now four pages of about sixteen columns each. The row stripes and the colours are printed rather than dropped, and come out as distinguishable greys on a mono printer. **The items you tick and the dates you choose are still the only print settings** — there is no second setup to fill in — and since each item now gets its own page, switching one off just removes a page rather than making room.

- **"Print class sheet" — one page that is everything you need to start scanning, and you can now find it.** The single most useful thing in the app was also the hardest to reach: student codes sitting in their seat positions with every activity code underneath, buried behind an unlabelled 🖨 button on the Dashboard, titled "Print: Seating chart" — a name describing how it is laid out rather than what it gives you. It is now **its own entry in Run**, named for the outcome, and it works on day one. **For a new rebbi the activity codes are included from the start.** They were an off-by-default checkbox, so the one-page-does-everything sheet only happened if you happened to find and tick it. **If you are already using Menchmark, nothing about your sheet changes** — whatever you have the activities footer set to now is what it stays. You print the same sheet every Monday and it will not quietly become a different one on a Monday you didn't ask for. The checkbox is still there, and it is now on a page you will actually come across, which is the real fix. **And it seats your class for you.** Before this, a rebbi who had imported his roster but never opened the seating chart printed a page of twenty-four boxes reading "Empty seat" — a sheet that looked real and had not a single student code on it. Anyone without a seat is now placed in roster order, the page tells you it happened, and **anyone you had already placed by hand stays exactly where you put them** — it only ever fills empty places, never moves a boy you positioned yourself. The seating is saved rather than being a one-off for the paper, so the chart on screen and the sheet in your hand always agree. **The grid is also sized to your class** rather than to a fixed 4×6 that was invented before anyone knew how many boys you have — a class of four gets a 2×2, sixteen gets a 4×4, instead of twenty-odd boxes reading "Empty seat" eating most of the page. **A chart you have arranged yourself is never resized**, empty places included: a gap in a row usually means something — an absent boy's seat, an aisle, the shape of the room — and moving it would break the map that is the whole reason to print a seating chart at all. **And the activity codes underneath now show their full names.** They were being cut short to fit — "Davening…", "Learning…", "Homewor…", "Bathroom…", "Undo Last…" — because each label was held to a single line inside a fixed-width card and trimmed with an ellipsis wherever it didn't fit. The whole job of that footer is letting you read a label at a glance while you scan, so a shortened name defeated it; labels now wrap onto a second line instead. **You can also fix the seating without leaving the page.** The chart editor — same rows and columns, same drag-to-rearrange, same one you already know — now sits underneath the sheet, so when the preview shows a boy in the wrong desk you move him right there and watch the sheet redraw, instead of going off to find the Dashboard. It is the same editor, not a copy, so the two cannot fall out of step. **Drag-to-rearrange switches itself off when you leave**, so a seating chart left in arranging mode can't be nudged by a stray touch on the smartboard during the next lesson. **Choose which codes go on it** (#117): a rebbi's activity list grows all year, and printing all of it defeats the point of a one-page sheet. Tick and untick, and it is **remembered** — the two Teach-mode phrase codes and −Custom start off, leaving the seven codes actually used in week one, and anything you add later appears by itself. Turning a code off leaves it off every printed sheet, and never stops you tapping it on the Dashboard. **Two smaller things:** the sheet used to head itself "All Classes" even for a rebbi with one named class who had never touched the class selector — it now uses the real name; and Portrait/Landscape is remembered instead of resetting to Portrait on every reload. **The other print pages are unchanged** — student labels, per-student pages and point cards all still work exactly as they did, from the same buttons. This is a front door, not a replacement.

- **The class sheet now prints properly when the chart needs more than one page.** A six-row chart broke badly: seat rows were **split across the page break** — a row starting on one page and finishing on the next — and the activity codes ended up stranded at the bottom of page two, away from the chart. Since the whole promise of this sheet is that one page carries everything you scan from, codes on page two are worse than no codes. Now **a seat is never split** by a page break, so a chart that genuinely needs two pages breaks cleanly between rows, and the **codes block is never split** either. **The codes stay underneath the chart, always** — the sheet is a seating chart with the codes below it, and that does not change with the size of your class. When everything fits, that is one page exactly as before. When the chart is too big for one page, the seats fill the first page and the codes follow on the last one, so you always know where they are. **And the warning that should have caught this now works.** The app checks whether your chart will fit before you print, but it was measuring the small preview on screen against the size of a sheet of paper — two different things, since a seat card is more than twice as tall in print as it is in the preview. It reported a comfortable fit on a chart that overflowed by about three inches, so nobody was warned. It now works out the real printed height, and tells you before you waste the paper.

- **Take attendance with the scanner: scan a boy to cycle him through present, absent and late.** Attendance is now an activity you can arm like any other — a button on the Record tab and a code on your printed class sheet — so you can take the roll from wherever you are instead of going to the Attendance tab first. **Everyone starts present**, which is how the tab already worked, so you only scan the exceptions. Scan a boy once and he is **absent**; again and he is **late**; again and he is **back to present**. **The cycle wraps on purpose:** scan the wrong boy and you fix it by scanning him again, rather than putting the scanner down and finding him on the tab. **Tapping a name on the Attendance tab does exactly the same cycle**, so the screen and the scanner can never mean different things — and the Present / Late / Absent buttons are still there when you want to set a state directly. Sending to your Google Sheet is unchanged. **One thing worth knowing about your Sheet:** changing a boy’s status is a new observation, so it sends that change — but a boy you did not touch is never re-sent. Tapping the state a boy is already on now does nothing at all, where before it quietly sent his row to the Sheet a second time. After changing one boy on a day you have already sent, the next send is **one row**, not a repeat of the whole class.

- **Fixed: your Google Sheet’s log tabs could get their header row written twice.** Sending attendance sends one row per boy, all at once, and Google runs those at the same time rather than one after another. Each one checked "is this tab empty? then write the header" — so when two arrived together, both found it empty and both wrote a header. You would see the column titles twice at the top of a brand-new **Attendance Log**. Only the header was ever affected: the rows underneath are one per boy either way. The same check sat in front of the **Log**, **Pesukim Log**, **Tracker Log** and **Homework Log** tabs, so all five are fixed together. **This is a change to the Apps Script**, so it only reaches your Sheet once you paste the new script and do **Manage deployments → New version** — until then nothing about your Sheet changes. If you already have a doubled header, delete the extra row by hand; nothing else needs touching.

- **The migration test harness now checks itself for drift against `app.html`, automatically, as part of every run.** `test-migration.html` keeps hand-copied duplicates of `migrateData()` and `load2fix()`, and until now nothing enforced that they stayed current — only a "keep in sync" comment and a command someone had to remember to run. That failure mode was silent and the worst possible shape: a stale harness cheerfully tests *old* migration code and reports all green, so a genuine regression in `app.html` passes the one gate meant to catch it. The harness now fetches `app.html` on each run, extracts both functions, normalizes them (strips comments, collapses whitespace — `app.html`'s copies are indented inside the app's IIFE while the harness keeps its own at column 0, so a raw byte diff is always noise), and compares. A mismatch is a loud red failure card naming which function drifted, both normalized character counts, and the first point of divergence with an excerpt from each side — because an edit that swaps one character for another leaves both counts identical, and a count alone would point nowhere. The extraction and normalization are deliberately character-for-character the same as the manual command in CLAUDE.md § "Validate before every commit" check 3, so the two can never disagree about whether the copies match. **If `app.html` can't be fetched** — most commonly because the harness was opened straight from disk via `file://`, where browsers block `fetch` — the check reports "could not run" as an amber card and the summary bar turns amber rather than green, with instructions for serving the repo over http. A check that was skipped is never allowed to look like a check that passed, which is the exact trap this whole feature exists to close. Harness-only: no application code, data model, or teacher-facing behavior is touched.

- **Instant (no-spin) toggle on the Picker, Spinner, and Raffle** — get an immediate result without the animation, shown until the next pick, remembered per tool. Requested by a rebbi who uses the Picker for fast repeated turn-taking and didn't want to sit through a 4–6 second spin every time. Each tool has its own saved checkbox (⚡ Instant), so you can make the Picker instant for quick turns while the Raffle still spins for the class. Each tool reveals its result in the way that suits it: the **Picker** shows the student straight away in both modes (the wheel snaps to them; the seating chart highlights the seat with no casino-flash build-up), the **Spinner** shows the item immediately, and the **Raffle** still announces the winner prominently with the same 🎉 Winner reveal and the same after-win options (keep / remove ticket / remove student) — only the wheel animation is skipped. The result stays on screen until the next pick replaces it. **Off by default in all three tools**, so nothing changes unless it's turned on. Purely presentational: who gets picked is unchanged — the same draw over the same entries, so ticket weighting, skip-had-a-turn, out/passed eligibility, and round-reset all behave exactly as before. New `data.pickerInstant` / `data.spinnerInstant` / `data.raffleInstant` booleans, backfilled to `false` in `load2fix()` (additive only — no `DATA_VERSION` change and nothing to migrate).
- **Menchmark is now installable as a PWA (Chrome app) with persistent storage and full offline support; QR library inlined so the app is dependency-free.** The QR code library (previously loaded from a CDN) is inlined into `app.html`, so the app has no external dependencies and works fully offline. A web app manifest (`manifest.webmanifest`, icons reused from the existing Menchmark mark) and a service worker (`sw.js`) make it installable ("Install Menchmark" from the browser) — it then runs in its own window and the browser grants **persistent storage** (via `navigator.storage.persist()`), which resists automatic data eviction. Storage-protection status is surfaced in Run → Backup & Sheets. The service worker serves HTML **network-first** so a new deploy always reaches users (no stale-app trap), with a versioned offline cache (`CACHE_VERSION`) and a "new version ready — reload" prompt. Additive only: no data-model or storage changes, existing `qrPointsData_v1` data is untouched, and the app behaves identically when not installed. **Note:** persistent storage does not override an admin-forced clear-on-exit or Guest-mode wipe on locked-down managed Chromebooks, so the Google Sheet backup remains the ultimate safety net (and is unchanged/undemoted).

- **Seating-chart student picker** — a new mode in the top-corner 🎡 Picker, alongside the existing wheel. Flashes through the eligible seats casino-style, decelerates, and lands on one student; already-picked students are dimmed (fair rotation made visible). **Tap a seat to cycle its eligibility** — in → out → skip today → in — so the rebbi can set who's available right on the chart, even before attendance is taken. Had-a-turn and eligibility are two **independent** facts with **one signal each** — had-a-turn is shown by dimming (a grey wash + faded name), eligibility by a single small OUT/PASSED pill — so all six combinations (picked/not-picked × eligible/out/passed) are distinguishable without repeating the same signal, and cycling eligibility never hides that a student already had a turn. Chart and summary read the same underlying state. Picker-only — tapping never changes attendance; "out" is merely pre-seeded from today's attendance. Shares the wheel's "already had a turn" turn-state and the "Reset round" button (reset clears turns and "skip today", keeps "out"). Built as a reusable, context-agnostic engine (`SeatPicker`) with clean inputs (cells / used / elig / config / interactive) and callback outputs (`onLand` / `onEligChange` / `onExhausted`), so future features (Jobs, etc.) can reuse it with their own data, turn-state, and eligibility. No new stored data — turn-state is the same in-memory `pickedSet` the wheel uses, and the eligibility overlay is in-memory too.
- **6-7 celebration:** optional full-screen animation when a student's total lands on exactly 67 points (plain-points mode only; off by default — toggle in Manage → Settings). Silent by design; two SVG hands do the weighing motion with a small confetti burst, then it fades out on its own or on a tap. Fires every time a total lands on 67, not just the first. New `data.sixSeven` boolean, backfilled in `load2fix()`.
- Quick Start guide (`quick-start.html`) with a Quick Start button in the app header — a 15-minute zero-to-first-scan walkthrough for beta rebbeim, opened in a new tab from the subheader next to the help button.
- Animated brand-story intro page — a scroll-driven GSAP sequence taking the "s" out of "mensch" and turning it into a scanner, ending on a split-screen frame (dark payoff line above, "Try Menchmark free" invite below). Includes a "▶ Play" button that smoothly auto-scrolls the whole animation so users can just watch (cancels the moment they scroll themselves). Now the site's front door (see Changed); also reachable from the landing page footer as "Watch the intro".

### Fixed

- **The scan box at the top of the screen was cut off, showing "Scan a QR code here (or ty" beside a wide empty gap.** The box was pinned to a fixed width no matter how wide your screen was, while the strip of recent scans next to it was set to take everything left over — so the box stayed stubby and clipped its own wording. On a class that has been running a while this was easy to miss, because the strip is full of recent scans and the space looks used. **On a brand-new install it was obvious**, since there are no scans yet and the strip is empty, leaving a small cut-off box next to a stretch of nothing. The box now grows to fill whatever the recent-scan strip isn't using, and the strip only takes the room its own entries need. **With a long list of recent scans nothing is lost** — the strip still fills the bar and older entries slide off the end as they always did, and the scan box keeps a sensible width instead of being squeezed.

- **The Gradebook no longer marks absences in red.** A boy with six absences printed as six red cells, and the Gradebook is a page a rebbi may well turn toward a parent. Red does not say *absent*; it says *guilty*, and a term's record should not open an argument about the boy before anyone has read a single date. **Absent and no-credit now sit in a quiet slate grey instead** — the same information, without the verdict attached. Late and partial credit keep their amber, present and full credit keep their green, so nothing has become harder to tell apart: slate and amber are further apart on screen than the old red and amber were. **The three shades are also deliberately held at the same visual weight**, so absences read as *noticeable* rather than as the loudest thing on the page — a record you can scan, not an accusation you have to defend. **And they now come out identical on a black-and-white printer.** This was caught by actually printing one: the shades were chosen to look right on screen, and the absent one happened to be a little darker than the others, which does not show on a monitor but on paper made every ✗ the heaviest mark on the page — the same problem as the red, arriving by a different route. The three are now matched so that a mono printer renders them as one flat shade, and the ✓ · L · ✗ do the work, which is what they were always there for. On a colour printer nothing changes. **Nothing about what is recorded changes**, and the cells still read ✓ present · L late · ✗ absent exactly as before: the mark in the box is what carries the meaning, and the colour behind it was only ever there to help you find it faster. The empty states are untouched — a day with nothing recorded is still the faint dot, and an unchecked homework is still a genuinely empty box. Presentation only; no saved data is touched.

- **Three things wrong with how the Gradebook draws, all visible the moment it had real attendance in it.** The grid shipped with nothing recorded against it, so none of this showed until the attendance conversion filled it in. **The Student column no longer has scrolled dates showing to the left of it.** Scroll a wide grid sideways and a narrow strip of the columns you had scrolled past stayed visible down the left-hand edge, overlapping where the student names should have been — the names column was doing its job, but stopped about 19 pixels short of the edge the card actually cuts off at, and the dates showed through the difference. The table now scrolls inside its own frame, whose edge lines up exactly with where the column stops, so there is no strip left for anything to show in. Fixed for the header as well as the rows, in both grid shapes. **The key underneath the grid no longer slides away when you scroll.** It was inside the part that scrolls sideways, so scrolling right to see later dates carried the key off to the left with it — by a few columns in, the Attendance key had gone entirely and the Homework one was cut off mid-word. It now sits still underneath the grid where it belongs, whatever the grid is doing. **And the cells now use a tick and a cross, so the exceptions are the thing you see.** The grid used to be letters throughout, and worse, the same letter could mean two different things in adjacent columns — Attendance showed **P** for *present* while Homework showed **P** for *partial credit*, with both explanations sitting in the same key looking like a contradiction. Attendance now reads **✓** present · **L** late · **✗** absent, and Homework **(empty)** unchecked · **✓** full credit · **P** partial credit · **✗** no credit. On a page of mostly-present boys the lates and absences stand out instead of having to be read letter by letter. **A value only gets a symbol where the symbol is genuinely obvious** — *late* and *partial* keep letters, because neither has a natural mark and both would be misread in the Total column, where the code sits directly against its count. **✓ and ✗ meaning the good and the bad outcome in both items is deliberate**, and is not the muddle that was fixed: they mean the same *kind* of thing wherever they appear, whereas *present* and *partial credit* were two unrelated facts sharing a letter. **Codes are fixed to the wording they stand for**, so they never shift because of what else you happen to be showing — turn Attendance off and Homework's codes are unchanged, and a page printed today matches one printed last week. **Your own scales still work**: an item with your own list of options falls back to initials as before, and if one of those would clash with a code already on screen it grows until it doesn't. **A homework marked *unchecked* now shows a genuinely empty box, while a day with nothing recorded at all still shows the faint dot** — those are different facts and used to look identical. Presentation only — nothing about what is recorded, stored or printed changes, and no saved data is touched.

- **A saved contest now keeps its own results, instead of quietly becoming an empty label.** "Save to history" only ever stored a contest's name, dates and mode — never anyone's scores. Re-saving a contest that is still running refreshes its stored results, and a contest still in progress always shows live numbers rather than a frozen snapshot. **What is kept and what is not:** the totals are saved, the scan-by-scan list underneath them is not — it stays tied to your real scan history, because that is what the ↩ undo arrows act on, and a list you could not undo from would be worse than an honest note saying the detail has aged out. ## [0.1.0] — 2026-07-08

Initial public release. Migrated from local file-sharing to GitHub.

### Added
- Point tracking via handheld scanner (USB keyboard-emulation or serial/COM)
- Activities with configurable point values
- Raffle (auto and manual modes)
- QR code label generation and printing
- Google Sheets sync (scan log + live standings)
- Backup/restore via JSON export/import
- Rebuild-from-Sheet-log recovery option
- Seating chart, spinner, and pass-tracking tools
- Settings for serial scanner baud rate and auto-reconnect

### Changed
- Genericized terminology throughout the app: "camp" → "school", "camper(s)" → "student(s)"
- Removed identifiable default values (real camp/bunk names) in favor of generic placeholders ("Sample School", "Sample Class 1")
- Removed the hardcoded Parshas Vayelech text from the app itself. The Pesukim tab now starts with an empty starter set; Vayelech is available as an importable example at `samples/vayelech-parsha-sample.csv`

### Notes
- This version does not yet include a `data.version` field or migration function. Adding one is a priority for the next release — see CONTRIBUTING.md for the pattern to use.
