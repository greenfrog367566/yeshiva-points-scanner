# Changelog

All notable changes to this project are documented here.

Format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project doesn't follow strict semantic versioning (it's a classroom tool, not a library), but version numbers roughly mean:

- **Major (v1.0.0 → v2.0.0):** big changes, possibly a new data format
- **Minor (v1.0.0 → v1.1.0):** new features
- **Patch (v1.0.0 → v1.0.1):** bug fixes only

## [Unreleased]

### Added

- **Gradebook: Homework cells are now editable too (#227, slice 2 of 4).** Same picker #248 built for Attendance — click a cell, pick a value, it writes through the legacy setter so the Homework tab and the Gradebook can never disagree. `setHw()` gained an optional `dateKey` parameter (mirroring `setAttendance()`'s own), so a correction from the grid can name a past day directly instead of only ever touching whatever day the Homework tab's own date picker happens to be showing. **The picker offers Checked / Not checked, not the full four-state cycle** — the Homework tab itself is still the old boolean store (unchecked/full credit are the only two states any writer can produce today), so "partial credit" and "no credit" stay display-only until #122 converts that tab to the real cycle. A blank cell is editable too, same as Attendance: "he never had his folder scanned" is as real a correction as "he did." Screen only — printed Gradebook pages are still built with editing off. **Homework and Attendance only, for now.** Passes and the Tracker column stay read-only in the grid — each of those stores still has to be taught to accept a correction for a past day before its column can be made editable.

- **The Help (?) modal's Scanner Setup tab now shows the actual Tera configuration codes, not just instructions to "scan the manual's barcode."** Tera gave written permission (2026-08-15) to reproduce their scanner's setup barcodes, so the barcode graphics themselves — cropped directly from Tera's own manual (`docs/Tera_UM1300_Manual.pdf`, now in this repo, sourced under `docs/tera-scanner-codes/`) rather than re-encoded from scratch — are now embedded inline next to the relevant explanation: Real-Time Mode/Storage Mode, Vibration On/Off, Clear Timestamp, USB-COM/2.4G Mode, and both flavors of factory reset (Wireless-only vs. full). A rebbi with a misbehaving scanner can now fix it from the app itself, scanning straight off the screen, instead of hunting through a printed manual. Support for markdown image syntax (`![alt](src)`) was added to the Help modal's `mdToHtml()` renderer to make this possible — it previously escaped all HTML, so an `<img>` tag pasted into the markdown source would have rendered as visible text rather than an image.

- **Undo now sits on the scan bar itself — one tap, everywhere.** Until now, the "reverse the last scan" button lived on the Dashboard (and on the History tab), which is precisely where you *aren't* while scanning: from the full-screen seating chart, or from any other tab, undoing a mis-scan meant opening the History dropdown and hunting for a small ↩ on the right row, mid-shiur. The scan bar — the strip that follows you to every scannable screen, including on top of the full-screen chart — now carries its own **↩ Undo** button, next to History. It reverses the most recent scan through the exact same path as the Dashboard button and the printed **Undo card** (which also still works, from wherever you're standing).

- **The app now remembers that you scan full-screen — and Settings lets you choose instead.** If you press **⛶ Full screen** on the seating chart and later close the browser from there, the next morning opens straight back into the full-screen chart — your scanning surface, ready to go — instead of starting you at the Dashboard every day. Pressing **✕ Close full screen** is what turns this off: the app takes that as "I'm done working this way" and goes back to opening on the Dashboard. Nothing to configure, and nothing changes for anyone who has never pressed ⛶. And if you'd rather not have the app guess, a new **Settings → How Record Opens** choice pins it: **Remember last** (the behavior above, the default), **Dashboard** (always start there), or **Full-screen chart** (always start in the room view). Changing it takes effect the next time the app opens — it never yanks the screen out from under you the moment you tap it.

- **Chazaroom: pausing the camera never restarts the quiz, and a "Live" badge follows you off the Play tab.** Previously, Stop Camera and Start Camera were a hard reset in disguise: Start's handler unconditionally wiped the game-so-far stats and dumped you back to the lobby, even if you'd only stopped to tweak the timer or fix a question — so the only way to "revert" a setting was to restart the whole game. Now `everStarted` tracks whether the camera has been started before this session; a later Start is a **resume** (new `resumeGame()`), picking back up at the same mode and question with scores intact, and only the very first Start of a session does the lobby/stats reset. A new **⏸ Pause** button sits right on the question board (`boardPauseBtn`) so pausing mid-question no longer requires detouring through the lobby first — the old detour was a trap, since the lobby's own "Start the game" button deliberately restarts at Q1 for its join/visibility check, which would have silently undone progress if reused as the resume path. A pill badge in the header (`#liveBadge`) shows "Live — Lobby" or "Live — Q*n* of *total*" whenever a game is running, on every tab, so hopping to Questions/Class/Answer cards to fix something never feels like it costs you the game — click it to jump straight back.

- **Chazaroom: a facelift for the header/nav**, borrowed from a UI mockup shown for comparison — a dark gradient command bar, a pill-shaped nav with a gold active tab, and a light crossfade when a section swaps in. Cosmetic only; no behavior changed beyond the pause/resume work above (same vanilla CSS, no new dependencies).

- **Chazaroom V3: the classroom is the primary screen.** The old five-tab structure treated Questions, Class and Answer cards as equal citizens with the live game — so setting anything up meant leaving the game screen entirely. Three changes, all with the same principle behind them: the rebbi should spend the whole shiur on the live screen, and everything else should come to *him*.

  **Setup moved into a slide-out drawer.** Questions, the class list and the printable cards now slide over the live screen from the right instead of replacing it — the running game stays visible (and running) behind a dimmed scrim, and ✕ / Esc / clicking outside drops straight back into it. Nothing inside those sections changed; only where they live. Printing the cards from inside the drawer still works.

  **The game screen is a two-column broadcast layout.** Left (~70%): the question board with a *large* camera feed directly beneath it — no more squinting at a 230px thumbnail to see whose scan just landed. Right (~30%): a live response panel — "*3 of 25 talmidim have answered — 22 to go*" with an A–D spread as horizontal bars. The spread honours the existing privacy rule (hidden until the reveal, so nobody copies the popular answer) with one deliberate exception: when the class has its own projector window, this screen is the rebbi's alone, and the spread runs live — seeing it early is the whole point of having his own screen. The mid-game leaderboard follows the same rule: off the class-facing screen (standings belong to the scoreboard beat), visible when presenting.

  **Three fixed classroom actions instead of one shape-shifting button:** *Show answers → / 🔒 Lock answers*, *Reveal answer*, *Next question* — always the same three, in the same place, with the gold one still saying what to press next. Lock is the "everyone commit" moment: it ends the answer window on the rebbi's schedule, triggering exactly the capture (lift popup + room scan) that the countdown reaching 0 triggers, so a class that answers fast never has to wait out the clock.

  Also fixed while in there: a `[hidden]` stat row could stay visible because the author `display:flex` beat the attribute (same quirk the tiles already carry a workaround for) — the anonymous-mode stats no longer show in roster mode.

  **The countdown holds while the setup drawer is open.** Both clocks — the get-ready beat and the answer countdown — freeze the moment a drawer opens and pick up at the same second when it closes, with the timer face showing ⏸ while held. Ducking out mid-question to fix a typo in the next question never costs the class answer time, and auto-reveal can never fire behind the drawer.

  **The "Lift up your cards!" popup no longer blocks the game.** It was a full-screen modal with a dark backdrop — which covered the camera feed and the response panel at precisely the moment the rebbi most needs them (during the capture, watching scans land). On the rebbi's screen it is now a compact floating banner over the board column: title, count, Pan-the-room / Reveal / auto-reveal, ✕ — with the tiles, the camera and the response panel all still visible and clickable around it. The class's own projector window keeps the full-screen takeover, because that's the screen the message is *for* — the boys need it big, the rebbi needs it out of the way. The who's-in chips are hidden on the rebbi's banner (the response panel already says who's in) but still render full-size on the projector.
- **A new rebbi's first app now shows the workflow, not the whole toolbox.** Finishing Quick Setup used to hand you the exact same app as a rebbi who's been running Menchmark for a year — Attendance, Homework, Tracker, Passes, Gradebook, Contest, Auction, Spinner and Trends all sitting in the nav on day one, next to the handful of tabs you actually touch to give your first points. From the UI design theory audit (`docs/UI_Theory_Tab_Audit.md`): those are real week-two-and-later tools, not day-one ones, and a brand-new rebbi can't tell which is which yet.

  **Now a fresh setup starts with those nine tabs hidden** — Attendance, Homework, Tracker, Passes, Gradebook, Contest, Auction, Spinner, and Trends — alongside the whole Review group, which already worked this way. What's left on day one is exactly the give-points-see-standings-redeem-in-store-run-a-raffle-print-your-sheet loop: Dashboard, History, Leader Board, Raffle, Store, Coin Deposit (if Shulchani), Students, Activities, Seating chart & print, Backup & Restore, and Settings.

  **Every hidden tab is one Settings checkbox away**, exactly like Review already was — this only changes what a *new* setup starts with. **Nothing changes for anyone already using Menchmark**: the write happens once, only inside the setup wizard's own completion step, and is skipped entirely when restoring from a backup or Sheet, so a rebbi's own saved nav choices are never touched or overruled.

- **Shulchani Mode: a Coin Deposit tab, for turning physical coins into a safe digital balance and back.** Until now a student holding real Shulchani coin tokens — from a reward, or handed out separately from a scan — had no way to get them off his desk and into the app. If he lost them, they were just gone; the app never knew they existed.

  **Rewards → Coin Deposit**, visible only in Shulchani Mode. Pick a direction (Deposit or Withdraw), pick a student — or scan his code while the tab is open to jump straight to his balance, exactly as the Store already does — and tap the coins he's handing you or receiving — one tile per denomination, smallest on the left up to the Darkon on the right, each with a −/count/+ stepper beneath it (tapping the coin itself also adds one) — building "2 Sela, 1 Dinar" the same way you'd count the physical pile on the desk. No typing. **All** (withdraw only) fills in his entire balance as its coin breakdown, **None** clears the count. Confirm, and it lands on his normal spendable balance, the same one Standings and the Store already use.

  **This is loss protection, not a bank account.** There is no separate "banked" pool, no interest, no savings goal — deposited coins are simply added to the balance he already has, the same way a Store purchase already subtracts from it. That's also why it's named "Coin Deposit" and not "Bank".

  **One tradeoff, made on purpose:** a deposit or withdrawal writes a single lump-sum entry, not the per-activity detail behind it — you'll see "Physical coin deposit" once, not a list of what earned those coins. A quiet note says so before you confirm. The entry is still fully visible in History, tagged with 🪙 so it reads differently from a normal scan.

  **Withdrawing is the same tool in the other direction**, and reintroduces the physical loss risk deposit exists to remove — the screen says so, but it isn't a blocking warning; a rebbi handing coins back to a student knows what he's doing.

  **What it deliberately does not touch:** Trends and lifetime-earned are unaffected, exactly like Store and Auction spending already work — spending never erases earning. Standings updates immediately, same as any other spend.

- **Hold every freeze at once when the whole room stops.** A freeze is a countdown, and until now it kept counting through anything — davening starting, an assembly, you being called out of the room. Three boys frozen while the class is not even sitting there means the consequence is served while nothing is happening, and it is over before anyone comes back.

  **Now a ❄️ Pause all button appears the moment anybody is frozen**, with the number of boys on it — next to "Give to all" on the Record tab, **and on the seating chart's own toolbar, including full screen**, popping in and out exactly the way the attendance ✓ button does, so it is there on the screen you actually scan from. One press holds every one of their clocks exactly where it is; the button becomes **▶ Resume all**, and one press starts them all again from the same time they stopped at. When the last freeze finishes the button takes itself away.

  **It only touches the class you are looking at**, exactly like "Give to all" — a boy in another shiur keeps counting down. Choose "All classes" in the top-right corner and it covers everyone.

  **If some are already paused and some are running, it pauses the ones still running** and leaves the others exactly as they are. Nothing is restarted and no time is added or lost, whichever way you press it.

  **This is the same pause the boy's own freeze box already had**, just applied to everybody at once — so a freeze paused this way is an ordinary paused freeze. Tapping that boy still opens his box, and Resume, Adjust and End freeze all work on him as usual.

- **You can now email the day's attendance to the office, from your own email.** Until now the only way attendance left Menchmark was into a Google Sheet — which is exactly right for a school that uses one, and no use at all to a school whose secretary simply wants an email every morning. A rebbi with no sheet connected pressed **Send Attendance** and nothing happened.

  On **Run → Attendance** there is now **✉ Email this day…** next to Send Attendance. It writes the message for you — the class, the date, the counts, and who was absent or late with the time he came in — and shows it to you before anything opens, so you can read it, add a line ("Dovid is at a bris"), and change it however you like.

  **It is sent by you, not by Menchmark.** Pressing **Open in my email app** hands the message to whatever you already use for email — Gmail, Outlook, Mail on an iPad — with the address and subject filled in. Menchmark does not send it, and never sees the address on any server: it is saved in your own browser, on your own computer, so the next day is one click. The office receives a normal email **from you**, which they can reply to.

  **Emailing is now the main button on the Attendance tab**, and the Google Sheet one says what it is: **Send to Google Sheets**. Nothing about the Sheet changed — it works exactly as before — it just no longer presents itself as *the* way to send attendance. The email is the one that works for every rebbi with nothing set up at all, which is why it is the button your thumb lands on. If no Sheet is connected, the tab now says so and points at the email instead of leaving you with a button that does nothing.

  **Every name carries the time it was marked**, not just the boys who came in late — with one line at the top saying so, since the same column means "when he walked in" under Late and "when you marked him" under Absent. It is what makes the email a record rather than a summary: the office can see the absences were taken at 9:04 and the boy who turned up was marked at 9:41.

  **Who was absent comes first, then who was late** — the two things an office actually has to do something about, at the top where they will be read. **＋ full list below** adds the whole class underneath with each boy's status, for a school that wants the complete roll on file; the absent and late boys appear there too, in their place in the list, so the bottom half is a roll and not a leftover. **Absent & late only** — just the top part — is the default, and whichever you pick is remembered.

  From the seating chart it opens as a **small window floating over the chart** rather than a new tab — so the chart is still there behind it, and closing the window puts you back exactly where you were instead of switching away from the class in front of you.

  **And you can send it without leaving the seating chart.** Arm Attendance, tap the boys who are away, press **✓ Mark the rest Present** — and an **✉ Email attendance** button appears next to it. One tap opens the email, already written, for today. It only appears once every boy has been accounted for, because half a roll arriving at an office is worse than none, and it disappears again by itself if somebody is left unmarked. This is the same message the Attendance tab writes, sent the same way — it saves the trip out of full screen, mid-shiur, to send the roll you have just finished taking.

  **And when a boy walks in after the email has gone, the next one is an update.** This is the ordinary case, not an edge case: you send the roll at 9:12, and at 9:40 the boy you marked absent walks in. Mark him late as usual — the button now reads **Email an update**, and pressing it writes a message that opens with **"Changed since the 9:12 AM email (1): Dovid Berkowitz — Late 9:40 AM"**, above everything else, because that is the only part the office hasn't already read. Its subject line ends in **— update**, so a secretary holding both messages can tell at a glance which one is current instead of comparing them line by line. The whole roll is rewritten underneath, so the update stands on its own even if the first email never arrived.

  Menchmark can only tell you it **opened** an email at 9:12, never that you sent it — pressing Send is yours, and it says so in those words. It does not touch your Google Sheet's own record of the day, which keeps working exactly as before.

The scan log only holds the last 500 scans and is deleted outright by "Reset all scores", so a contest's results faded away as the class kept scanning, and vanished completely on a reset. A rebbi could run a contest for three weeks, press Save, and be left with a name and nothing behind it.

Either way the contest moves to **Finished contests** on the same tab, keeping its full per-boy results as a permanent read-only record — after adding points it is the only thing that explains why a boy's score jumped, and after letting them go it is the only record the contest ever happened. Each finished contest has its own "Remove from history" button, so pruning that list is always your deliberate choice, and its confirmation says exactly what removing it does and does not undo.

Those are what made the old lifecycle hard to reason about — including the end-contest dialog that promised a contest's history would survive while the OK button underneath it deleted the scan log that history was computed from.   **Nothing existing is touched, and no saved data can be lost.** Two brand-new fields are added (`miniContest`, `miniContestPast`) and nothing else is read, renamed, converted or removed — so there is no data-version change, and a save from before this update loads exactly as it did, simply gaining "no contest is running". - **The throwaway localhost servers development sessions leave running are now cleaned up automatically.** Looking at `app.html` in a real browser means starting a small local web server, and nothing ever stopped one again — the session ended, the server kept listening. Thirteen were found running at once on one machine, five of them from the previous day and no longer answering at all; only one belonged to a session that still existed. A hook now reaps them: **on session start** it kills servers whose session is gone, and **on session end** it kills the ones that session itself started. The two layers are not redundant — session-end never fires when a session is force-quit or crashes, which is exactly how all thirteen accumulated, so the session-start sweep is the one that actually holds. **It is built to under-kill rather than over-kill**, because the same `node` that runs a preview server also runs the editor's own background services, and killing one of those breaks a live session. A process is only ever touched if it is `node`, *and* is listening on a TCP port (the editor's services talk over stdio and never listen, so they cannot match), *and* its command line looks like a dev server, *and* it is on a dev port or references this repo — and even then, never while a live session sits anywhere up its parent chain. Anything ambiguous is left running. A newly orphaned server gets a 30-minute grace period so a preview still open in a browser tab isn't yanked out from under you, and **every kill is logged** to `.claude/reap-dev-servers.log` with the port, age and command line, so a surprise is always explainable afterwards. A server started by hand from a terminal has no session above it and so cannot be told apart from an abandoned one — its port can be pinned (`MENCHMARK_REAP_SKIP_PORTS`) and it is then never touched. Can be run by hand, including a `-DryRun` that reports what it would kill and touches nothing. Dev-only — no app behavior changes, nothing touched in the app or its data. See `.claude/hooks/reap-dev-servers.ps1`.

- **A Coin Guide for the class — Shulchani Mode finally explains itself to the boys whose scores it is written in.** Shulchani Mode swaps numbers for Talmudic denominations, which is the point of it; what it never came with was **anywhere a talmid could find out what they are worth**. A boy looks up at the Leader Board, sees **1 Dinar, 1 Maah, 1 Pundion, 1 Isar, 2 Prutah**, and has no way to tell whether that is more or less than the boy above him — the conversion table existed only inside the app's code and in whatever the rebbi had written on the board himself. **🪙 Coin Guide** now opens from the **Leader Board** and the **Prize Store**, and from **Settings → Shulchani Mode**. It has four parts: **the ladder** — every coin, biggest to smallest, colour-matched to how the app already prints it, with what it is worth in Prutot and what it is worth in the coin below it (1 Dinar = 6 Maah, 1 Isar = 8 Prutah); **how to read your balance**, including the one thing that genuinely confuses a boy the first time — that **earning can make your pile smaller**, because 7 Prutah plus one more Prutah is 8 Prutah, which is exactly 1 Isar; **worked examples** that show the arithmetic rather than the answer, stepping through *take the biggest coin that fits, subtract it, keep going* for five balances; and **a converter** — type any number, or tap one of the ready values, and watch it turn into coins. **It is built for the projector** — it opens over whatever tab you are on, so a boy asking "what's a Maah?" mid-scan is answered without leaving the screen and losing your place. **And it prints two ways, because the room and the boy need different things.** **🖨 Wall chart** is the one-page version for the board or the wall, in the same colours. **🪪 Pocket cards** prints **a sheet of ten identical business-card-sized cards** — the seven coins, their values and their rates, small enough to live in a sefer or taped inside a desk, so a talmid who wants to work out his own balance never has to ask. **A dropdown picks the sheet, the same way the student labels do** — **Avery 5911** business cards (3½″ × 2″), **Avery 5163 / 8163** (4″ × 2″), or **Cut out** on plain paper — **ten cards per sheet on all three**, with a note under it telling you what to load and what to set in the print dialog. **The two Avery options are looked up from the same `LABEL_SPECS` table the student labels use** rather than restated, so the guide and the labels can never disagree about where a card sits on the page; each carries that stock's real die-cut margins and gutter, and all three come to exactly 8½″ × 11″. **Cut guides appear only on plain paper** — ruling dashed lines onto real label stock would draw them straight across the cards. **Your choice is remembered.** The coloured dots are forced to print, since browsers drop background colours by default and the colour is the one thing tying the card to the board. **Every number in it is generated from the app's own coin table at the moment you open it**, deliberately: a conversion chart typed into the page would be a second copy of the same values, and the first time a denomination moved, the guide would carry on teaching arithmetic the app no longer does, with nothing to catch it. **The Leader Board and Store buttons only appear in Shulchani Mode**, since in points mode there is nothing to convert;   **The cause: the app was looking for the scanner by counting, not by name.** On reopening, it asked the browser which serial devices this computer had given it permission for, and reconnected **only if there was exactly one.** One single leftover permission — an older scanner, a Bluetooth-SPP device, a virtual COM port some other program installed — and the count came back as two, and the app quietly did nothing at all. ### Fixed

- **Print bug fix: scan bar and sub-tab icons no longer appear on any printed output.** The `#globalScanBar` element and the `.subtabs-row` / `.subtabs-icons` elements are now explicitly hidden in all `@media print` rules. Previously they leaked into every print job, appearing as stray icons at the top of the page.
- **Seating chart print bug fix:** the scan bar was appearing at the top of seating chart prints.
- **Apps Script (Code 1): Leader Board tab never rebuilt after the first student.** The sort comparator inside `rebuildLeaderBoard()` called `lastFirstKey()`, which exists in the browser app but was never defined in the Apps Script. The function threw a `ReferenceError` on every `doPost` call once 2+ students existed — log rows were written correctly, but the Leader Board sheet tab silently never updated. `lastFirstKey` is now defined in Code 1 itself. Users who already deployed should re-paste Code 1 and redeploy (Manage deployments → ✏️ → New version; your URL stays the same).
- **Undo buttons could reverse the wrong scan.** Deferred Undo buttons (Recent scans panel, History tab, scan strip, Contest views) captured a log array *index* at render time. `addLogEntry()` unshifts the array, so any scan that lands between render and click shifted all indices — the button would silently undo a different student's entry. All deferred handlers now look up the entry by its stable id at click time.
- **History/contest dropdowns closed on clicks inside themselves.** The outside-click handler for the History and Activity dropdowns in the header bar used a selector (`#seatsScanTile`) that matched no element, so every bubbled click — including clicks on Undo rows *inside* the dropdown — was treated as "outside" and closed it. Fixed to correctly identify the dropdown containers.
- **Duplicate event listener on the Contest tab's student filter.** The `#contestHistFilter` select had the same `change` handler registered twice. The second one re-rendered the entire Contest tab on every filter change, wiping each Past Contests card's own local student filter. Removed the redundant registration.
- **Corrupted `localStorage` value crashed the entire app.** `JSON.parse` can succeed on a non-object (`"42"`, `"null"`, etc.); `load2fix()` then threw trying to assign properties to a primitive, producing a white screen with no way to recover. `load()` now only accepts a parsed plain object and falls back to defaults for anything else.
- **Restoring a backup left half the UI showing pre-restore state.** After a JSON restore, the class dropdown still listed the old classes; the tap panel, live board, scan-tab layout, and settings-driven UI (full width, header shortcuts, Hebrew date) all kept the previous session's state until some unrelated action happened to re-render them. The restore handler now explicitly refreshes everything the restored data drives, and runs `migrateData()` for version stamping (same as the normal load path).
- **"Resync all scans" could append duplicate rows to Google Sheets forever.** Log entries rebuilt from a Log CSV, and legacy entries predating the id field, had no `id`. The sheet's dedupe check keys on that field, so every Resync click re-appended id-less entries — there was no way to stop the accumulation. CSV-rebuilt entries now get a stable id at import time, and `load2fix()` backfills ids onto any legacy entries on first load.
- **Game timers (Memory, Match, Quiz, Pesukim Matching) kept firing after navigating away.** The 100 ms tick intervals for the shorashim Memory, Match, and Quiz games, and the Pesukim Matching game, had no self-cancel guard. On a smartboard left running all day they accumulated, touching the DOM of hidden views each tick. Each timer now self-cancels when its view leaves the screen, matching the behavior the Game Show timer already had.
- **Beep sounds silently dropped when the AudioContext was suspended.** Browser autoplay policy can leave a previously-created `AudioContext` in a `suspended` state (e.g. after backgrounding the tab). Subsequent calls to `beep()` produced no sound. `beep()` now resumes a suspended context before playing.
