Chazaroom ArUco Sandbox
Wand detection prototype — not wired into the game

1 · Generate wand labels

Print at 100% / actual size ("Fit to page" will throw off the alignment) with margins set to "None" in the print dialog. The dashed cell outlines are a screen-only alignment guide and do not print. Each wand is a 4-sided foam cube on a wooden dowel — one label per face, glued so the printed TOP arrow points the same physical direction on all four faces. Twisting the cube to show a different face to the camera is how a student changes their answer; the Live Scanner tab decodes which wand and which lettered face is currently visible.

1 · Camera

Camera names are hidden until you grant permission once.

Requests the highest resolution the camera offers, up to 4K, and falls back to 1080p then to whatever the browser grants if that's refused. Detect width is the separate lever that controls detection cost — it downsamples the frame handed to the detector (never upsamples); lower it if the passes/sec stat below is too low for your marker density, at the cost of range on small/distant markers.

Three false-positive filters, applied in this order before a marker can reach the results panel: roster whitelist (a detected ID's wand number — floor(id/4) — must be below the roster size, and any ID at or above the reserved room-calibration range is dropped outright regardless of roster size — a stray read off a random barcode or book cover almost never lands inside that combined range), N-frame confirmation (a new ID must appear in N consecutive detection passes, with no gap, before it counts — filters one-off transient misreads from motion blur or partial views, and from the moment a cube is mid-twist between two faces), and an optional center-zone ROI (ignore anything whose marker center falls outside the dashed box, for setups where only a defined "voting zone" should count). On the overlay, markers still building their streak are drawn amber/dashed; confirmed ones are green.
